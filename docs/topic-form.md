# 주제 제출 양식 초안 (kirothon 사이트 · 5팀)

> 카테고리: **농생명 산업 지역경제** · TOPIC 13. `## ` 아래 본문을 각 칸에 그대로 붙여넣는다. 글자 수는 칸 제한 이내로 확인했다.

## 서비스명

잇다랩

## 한 줄 소개

AI 도입이 막막한 전남 기업의 한 줄 요구를 학생 팀이 할 수 있는 프로젝트로 정리하고, 기술이 맞는 광주 AI 인재를 추천 이유와 함께 연결하는 서비스

## 문제 정의

전남의 중소기업은 AI를 도입하고 싶어도 무엇을 맡겨야 하는지, 어떤 기술을 가진 사람이 필요한지 정리하지 못합니다. "불량품 고르는 데 사람이 너무 많이 든다, AI로 안 될까" 같은 막연한 요구만으로는 학생 팀이 프로젝트를 시작할 수 없고, 진행 중에도 범위가 계속 바뀝니다.

반대로 광주는 AI 교육과 인재가 모인 도시이지만, 학생들은 전남 기업에 어떤 프로젝트가 있는지 알 경로가 없습니다. 실전 경험을 찾아 수도권으로 떠나고, 2025년 연간 인구 순유출률은 광주가 전국 최상위권이었습니다(국가데이터처 국내인구이동통계).

지금의 연결 방법은 교수·지인 소개나 산학협력 공고 게시판뿐이며, 기업의 요구를 정리해 주거나 학생의 기술과 얼마나 맞는지 비교해 주지 않습니다. 팀장도 지역 기업과 산학협력 프로젝트를 진행하며 가장 어려웠던 점이 개발이 아니라 회사의 요구를 프로젝트 범위로 정리하는 일이었습니다.

전남광주통합특별시 출범으로 광주의 AI 인재와 전남의 산업 현장을 잇는 일은 통합의 실질적인 효과를 보여줄 수 있는 문제입니다. 잇다랩은 이 연결의 첫 단계인 "요구 정리"와 "적합한 사람 찾기"를 AI로 해결합니다.

## 핵심 기능

1. 프로젝트 범위 정리
   - 기업이 자유롭게 쓴 요구를 Bedrock이 목표 한 줄, 필요 기술(기술 사전에서 최대 5개), 산출물(최대 3개)로 구조화합니다.
   - 기업은 결과를 확인·수정한 뒤 프로젝트로 등록합니다.

2. 적합도 매칭과 추천 이유
   - 학생의 기술 프로필과 프로젝트의 필요 기술을 비교해 점수를 계산합니다. 점수는 코드가 계산해 같은 입력이면 항상 같은 결과가 나옵니다.
   - AI는 겹치는 기술과 부족한 기술을 근거로 추천 이유를 2문장 이내로 설명합니다.
   - 기업은 "우리 프로젝트에 맞는 학생", 학생은 "나에게 맞는 프로젝트"를 양방향으로 봅니다.

3. 관심 프로젝트 저장
   - 학생이 관심 있는 프로젝트를 저장하고 목록으로 다시 봅니다.

시연 데이터: 팀이 직접 만든 가상 인재 10명과 전남 기업 프로젝트 10건.
제외 범위: 실제 채용 결정, 실제 개인정보·이력서 사용, 기업 채용 시스템 연동.

## 활용 AWS 서비스

- Amazon Bedrock (Claude Haiku 4.5, Converse API): 프로젝트 범위 정리, 추천 이유 생성
- Amazon EC2: 팀 서버에서 Nginx + FastAPI + SQLite로 서비스 운영
- AWS IAM 역할: 액세스 키 없이 서버 권한으로 Bedrock 호출
- Amazon S3 (선택): 팀 버킷에 시연 데이터·결과 보관 검토

## Kiro 활용 계획

Steering
- 운영진 공통 규칙 5개(기술·구조·배포·데이터·AWS)를 유지하고, 팀 규칙 2개를 더했습니다.
- product.md: 문제·데모 시나리오·핵심 기능 3개·제외 범위, AI 응답 256토큰·지시문 300자 제약, "점수는 코드, 설명은 AI" 원칙
- file-rules.md: 루트에 새 파일 금지, 일회성 코드는 scratch/, 팀 코드는 backend/app/team/에만

Generate Specs
- 기능마다 requirements → design → tasks 순서로 만들고, 단계마다 팀이 검토한 뒤 다음으로 넘어갑니다.
- requirements에는 검증 가능한 완료 조건을, design에는 팀 테이블 컬럼·API 요청/응답·점수 공식·AI 지시문을, tasks에는 30~60분 단위 작업과 담당자·요구사항 번호를 적습니다.
- 로컬 mock 통과와 팀 서버의 실제 Bedrock 검증을 구분해 verification.md에 기록합니다.

Hooks
- Agent Stop: 매 턴이 끝날 때 구조 검사 스크립트를 실행해 루트의 새 파일, .env·DB 파일 커밋을 잡습니다.
- PreToolUse(write): 파일을 쓰기 전에 AWS 키·비밀번호가 코드에 들어가는지 확인합니다. 저장소가 Public이기 때문입니다.
- 매칭 점수 테스트가 생기면 백엔드 파일 저장 시 pytest를 실행하는 hook을 추가합니다.
