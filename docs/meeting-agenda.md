공공 SI 프로젝트가 많다는 멘토 지적(멘토링 2, 01:56)에 따라 Java·Spring·전자정부 표준프레임워크를 사전에 추가할지 design.md에서 정한다.

**적합도 공식 (초안, design.md에서 확정)**: 확장 기술이 새로 생겨서 옛 공식을 고쳤다.

```
기술 점수 = (보유 기술 일치 수 + 확장 기술 일치 수 × 0.5) ÷ 필요 기술 수 × 80   (최대 80)
조건 가산 = 근무 형태가 맞으면 20, 아니면 0
총점 = 기술 점수 + 조건 가산   (소수점 버림, 동점이면 보유 기술 일치 수가 많은 순)
```

## 6. AI 출력 형식 (옛 안건 §6에서 유지)

- 출력은 JSON이 아니라 **줄 단위 텍스트**다. 256토큰에서 JSON은 잘리면 파싱이 깨진다
- instruction은 300자 이내로 쓴다. 기술 사전 목록은 instruction이 아니라 text에 넣는다
- 숫자는 코드가 넘긴 것만 쓰게 한다

| 기능 | instruction 초안 (김민서가 다듬는다) |
|---|---|
| ① 해석 | 자기소개를 읽고 정확히 4줄로 답하세요. 기술: 함께 준 목록에서만 최대 5개, 쉼표로 구분. 확장: 이 경험으로 할 수 있는 목록 속 기술 최대 3개. 조건: 본가출퇴근=예/아니오, 차량=있음/없음, 근무=상주/재택/무관. 근거: 한 문장. 입력에 없는 사실은 쓰지 마세요. |
| ② 분석 | 사용자 조건, 프로젝트 정보, 계산된 금액을 보고 정확히 3줄로 쓰세요. 맞는 점: 한 문장. 아쉬운 점: 한 문장. 판단: 한 문장. 금액은 주어진 숫자만 그대로 쓰고 새 숫자를 만들지 마세요. |
| ③ 로드맵 | 선택한 회사들의 필요 기술과 사용자 기술을 비교해 정확히 4줄로 쓰세요. 1개월: 할 일. 3개월: 할 일. 6개월: 할 일. 경력: 이 회사에서 1년 일하면 얻는 것 한 문장. 주어진 정보에 없는 회사 사실과 숫자는 쓰지 마세요. |
