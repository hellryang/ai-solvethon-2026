# 제품 정의

> 주제 확정: **TOPIC 13 광주 AI 인재와 전남 기업 프로젝트 매칭** (2026-10-30). 서비스 이름은 팀이 정하면 바꾼다.

## 한 줄 요약

전남 기업이 막연하게 적은 "AI로 이런 걸 하고 싶다"를 학생 팀이 할 수 있는 프로젝트 범위로 정리하고,
기술이 맞는 광주 AI 인재를 추천 이유와 함께 연결한다.

## 해결하는 지역 문제

- **누가**: AI를 도입하고 싶은 전남 중소기업, 실전 프로젝트 경험이 필요한 광주 AI 전공 학생
- **무엇 때문에 곤란한가**
  - 기업은 AI로 무엇을 맡길 수 있는지, 어떤 기술을 가진 사람이 필요한지 정리하지 못한다. 요구가 막연하면 학생 팀은 시작하지 못하고, 진행 중에도 범위가 계속 바뀐다
  - 학생은 광주에 AI 교육·인재는 몰려 있지만 전남 기업의 프로젝트를 알 경로가 없다. 그래서 경험을 찾아 수도권으로 간다
- **지금은 어떻게 하나**: 교수·지인 소개, 산학협력단 공고 게시판. 기술 적합도를 비교하지 않고 공고만 나열한다
- **근거**
  - 2025년 연간 인구 순유출률은 광주가 제주와 함께 전국 최상위권 (국가데이터처 국내인구이동통계, 2026-01 보도)
  - [청년층 순유출 수치 — 국가데이터처 시도별 연령 표에서 확인 필요]
  - 팀장 경험: 지역 기업 산학협력 프로젝트(4인 팀, 2026.07~09)에서 요구 범위를 중간에 다시 잡아야 했다 (예: 연동 대상 하나가 회의에서 범위 제외됨)
- **전남광주통합특별시 관점**: 광주의 AI 인재와 전남의 산업 현장을 잇는 것이 통합의 실질적 효과다

## 데모 시나리오 (발표 때 라이브로 보여줄 한 흐름)

1. 전남의 농산물 가공 기업이 "불량품 고르는 데 사람이 너무 많이 든다, AI로 줄이고 싶다"고 한 줄로 등록한다
2. AI가 이를 프로젝트 범위로 정리한다 — 목표 한 줄, 필요 기술(예: 이미지 분류, 데이터 라벨링, 웹 대시보드), 산출물
3. 가상 인재 10명 중 적합도 상위 학생이 점수·추천 이유·부족한 기술과 함께 뜬다
4. 학생 화면에서 같은 프로젝트를 "나에게 맞는 프로젝트"로 보고 관심 프로젝트로 저장한다

## 기능 범위

| 우선순위 | 기능 | 담당 |
|---|---|---|
| P0 | **프로젝트 범위 정리**: 기업의 자유 서술 요구 → Bedrock이 목표 1줄·필요 기술(기술 사전에서 최대 5개)·산출물 최대 3개로 구조화. 기업이 확인·수정 후 등록 | |
| P0 | **적합도 매칭과 추천 이유**: 학생 기술 프로필 ↔ 프로젝트 필요 기술을 비교해 점수를 내고, 추천 이유와 부족한 기술을 설명 (기업→학생, 학생→프로젝트 양방향) | |
| P0 | **관심 프로젝트 저장**: 학생이 프로젝트를 저장하고 목록으로 본다 | |
| P1 | 팀 구성 제안: 한 프로젝트에 기술이 서로 보완되는 학생 3명 조합 추천 | |

P1은 P0가 배포 URL에서 끝까지 동작한 뒤에만 시작한다.

## 매칭 원칙 (spec 작성 때 그대로 쓴다)

- **점수는 코드가 계산하고, 설명은 Bedrock이 쓴다.** 같은 입력이면 항상 같은 점수가 나와야 테스트할 수 있고 심사에서 설명할 수 있다
- 기술은 정해진 목록(기술 사전)에서 고른다. 자유 입력 기술은 AI가 사전 항목으로 맞춘다
- 추천 이유는 반드시 "겹치는 기술"과 "부족한 기술"을 근거로 쓴다. 근거 없는 칭찬 문장 금지
- 데이터: 가상 인재 10명 + 기업 프로젝트 10건을 팀이 직접 만들어 넣는다 (주최측 가이드)

## 공통 스타터 제약 (운영진 r2 — `aws.md`·`data-policy.md`)

- AI 응답은 **최대 256토큰**, 입력 text 최대 4,000자, instruction **최대 300자**. 그래서 AI에게는 짧은 결과만 맡긴다
  - 범위 정리: 목표 1줄 + 기술 키워드 최대 5개 + 산출물 최대 3개
  - 추천 이유: 학생 1명당 2문장 이내. 여러 학생의 이유를 한 번에 몰아서 요청하지 않는다
- 호출 한도는 팀 서버 기준 분당 20회·하루 600회. 매칭 화면을 열 때마다 AI를 부르지 않도록, 점수는 코드로 계산하고 AI 설명은 버튼을 누를 때만 요청한다
- AI 호출은 공통 `ai_service`를 거쳐 호출량 제한을 받는다. 팀 코드에서 boto3로 Bedrock을 직접 부르지 않는다
- 로컬은 mock 응답이다. AI 품질 확인은 통합 담당자가 팀 서버에 배포한 뒤 한다
- 팀 테이블(인재·프로젝트·관심 저장)은 `backend/app/team/models.py`, API는 `team/routes.py`. 한 번 배포한 테이블의 컬럼은 바꿀 수 없으니 **첫 배포 전에 컬럼을 확정한다**
