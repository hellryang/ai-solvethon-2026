# 구현 작업 — 광주 AI 인재 ↔ 광주·전남 기업 프로젝트 매칭 (5조)

- 근거: `requirements.md`(R1~R13), `design.md`.
- 담당 표기: **통합**(통합·배포), **화면**, **API**(API·데이터), **AI**(AI·검증), **문서**(문서·시연).
- 우선순위: **P0** 필수, **P1** P0 완료 후, 시간 단위는 대략 30~60분이다.
- 서버와 계정은 **10월 31일(토) 20:00에 삭제**된다. 마감 전 Git push와 서버 확인을 끝낸다.
- 서버 작업(Check, Deploy)은 통합 담당자 한 명만 한다. 나머지는 로컬(mock)에서만 개발한다.

## 진행 순서 요약

```
0 합의·데이터 확정 ──▶ 1 기반(스키마 게이트) ──▶ 2 계산 모듈 ──▶ 3 API ──▶ 4 AI
                                      │                          │
                                      └──────────▶ 5 프론트 (API 계약 합의 후 병렬)
                                                       6 P1 기능 ──▶ 7 통합·배포 ──▶ 8 시연 준비
```

계산 모듈(2)은 DB와 AI를 쓰지 않으므로 1과 병렬로 시작해도 된다. 프론트(5)는 design.md §9의 API 계약이 합의되면 mock 응답으로 먼저 만들 수 있다.

## 실패 시 원칙

- 원인과 배포 ID를 보고하고, 기존 배포 도구로 **코드만** 복구한다.
- DB와 호출량 기록을 초기화하거나 과거로 되돌리지 않는다.
- 스키마 검사에서 멈추면 검사를 우회하지 말고 컬럼 변경을 되돌리거나 새 테이블로 옮긴다. 필요하면 멘토에게 검토를 요청한다.
